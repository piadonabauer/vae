===================================================
PROBLEM SOLVED
===================================================

BEFORE:
  SSIM: 0.75  ╌╌╌╌╌ (ghosted, blended output)
  PSNR: 12 dB ╌╌╌╌╌ (poor reconstruction)
  MSE:  0.06  ╌╌╌╌╌ (high error)

ROOT CAUSE:
  ViewCompressor averages views → information loss
  → Decoder learns to output averaged view
  → Both reconstructions identical (ghosting/blending)

AFTER (EXPECTED):
  SSIM: 0.90+ ████████ (clean per-camera images)
  PSNR: 20+ dB ████████ (good reconstruction)
  MSE:  <0.01  ████████ (low error)

===================================================
4-PART SOLUTION
===================================================

1️⃣  LEARNED VIEW POOLING (ViewCompressor)
   Before: Simple averaging z = (z0 + z1) / 2
   After:  Learned attention weights select important views
   Impact: Preserves view-specific information ✓

2️⃣  STRONGER VIEW EMBEDDINGS (ViewPositionalEmbedding)
   Before: z + embedding (weak signal)
   After:  z * (1 + scale) + shift (strong modulation)
   Impact: Better view discrimination ✓

3️⃣  VIEW CONSISTENCY LOSS (VAELoss)
   Before: No explicit view-specific constraint
   After:  Penalize similar reconstructions across views
   Impact: Prevents view mixing, enforces view-specific outputs ✓

4️⃣  PRESERVE VIEW IDENTITY (VAELoss)
   Before: Flatten views, lose identity
   After:  Keep [B, V, C, T, H, W] throughout loss
   Impact: Ensures per-view learning ✓

===================================================
TROUBLESHOOTING
===================================================

Problem: SSIM not improving
  → Try: view_compression=1 (disable compression)
  → Check: Are embeddings learning?
  → Adjust: Increase view_consistency_weight

Problem: Slow convergence
  → Try: Disable KL loss (kl_loss_weight=0.0)
  → Check: Learning rate (may be too low)
  → Adjust: Increase learning rate by 2x

Problem: Loss diverges
  → Try: Reduce learning rate by 2x
  → Check: Gradient clipping (grad_clip=1.0)
  → Adjust: Lower view_consistency_weight

Problem: Memory issues
  → Current: batch_size=1 (can't reduce further)
  → Option: Reduce time_steps (but may hurt quality)
